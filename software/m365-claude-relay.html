M365 Claude Relay.

Microsoft 365 for Claude custom connectors — each user acts as themselves.

Give Claude your users’ own Outlook mail, calendar, contacts and OneDrive through one small service you run. Sign-in is Microsoft’s own (Entra On-Behalf-Of): the relay never holds a password, never stores a token on disk, and exposes exactly the tools your chosen Graph scopes cover. Works with Claude on the web and desktop, on Free, Pro, Team, and Enterprise plans.

The relay as a Claude custom connector: read-only Microsoft 365 tools, set to Always allow.

Why this exists.

We built it because Claude’s native Microsoft 365 connector can’t send, forward, or draft mail with attachments. A user on a managed tenant needed Claude to work with their mail — and the mail had attachments.

Anthropic’s documentation is explicit: “Attachments aren’t supported in write tools, so sending, forwarding, and drafting all reject messages with attachments,” and “Claude can’t attach files to the drafts it creates.” The relay reads any attachment as a real file and sends, forwards, and drafts with files up to 150 MB — on mail and on calendar events.

The native connector is also limited to a fixed set of tools chosen by Anthropic, refuses personal Microsoft accounts, and requires a Global Administrator to consent to Anthropic’s app for the whole tenant. The relay is Softeria’s open-source Microsoft 365 MCP server, run yourself with your own app registration and your own scope list.

What it is.

One container you run. The server is Softeria’s ms-365-mcp-server (MIT), run in On-Behalf-Of mode, with no gate or custom code of ours in front of it. Everything the relay once added in front of Softeria — the token checks and tenant allowlist, attachment upload links, read-mail-text, and more — is now part of Softeria itself, through our upstream pull requests (#693, #694, #695, #703, #708, #733, #736).

The image is our build of Softeria 0.176.0 with two fixes we have submitted upstream and Softeria has not yet released: no mail content in any log, bounded log files, and a startup credential check (#775); and delete that moves mail to Deleted Items, as Outlook does, with permanent delete kept as a separate tool (#777). Once Softeria releases both, the relay goes back to Softeria’s own image. Our repository holds the configuration for Claude, the deployment and verification guide, the Entra and Claude setup, and the Claude skills.

Identity

Each user acts as themselves.

  1. The Claude connector points at your relay. Claude sends the user through Microsoft sign-in with the relay’s app registration, and the user consents to the configured Graph scopes.
  2. Microsoft issues Claude a token for the relay, which Claude keeps and refreshes.
  3. On every call the relay exchanges that token On-Behalf-Of the user for a Graph token, held in memory — Entra verifies the token at the exchange — and calls Graph as that user.

The relay has no standing access to any mailbox.

Scopes

Scopes decide the tool surface.

The policy is a list of Microsoft Graph scopes. Every tool whose required scopes that list covers is exposed; users consent to exactly those scopes at sign-in. The default seven — profile, mail, send, calendars, contacts, mailbox settings, and OneDrive — expose 139 tools on a personal account and 140 on a work tenant.

Scopes are runtime configuration: change MS365_MCP_ALLOWED_SCOPES and MS365_MCP_EXTRA_SCOPES and restart, no rebuild. On a work tenant, admin-consented scopes unlock Teams, SharePoint, shared mailboxes, Planner, and directory tools.

Claude stays in charge of each tool.

Once connected, Claude’s own per-tool permissions decide what each user can actually use: Always allow, Needs approval, or Blocked, with an org-admin ceiling on Team and Enterprise. A blocked tool is removed from Claude’s tool set entirely, and anything the account itself lacks simply fails at Microsoft — nothing runs that the scope does not allow.

Write tools — creating events, drafts, folders — set to Needs approval.

Deploy it.

Four steps. Full instructions are in the repository.

Running on Azure? Follow the step-by-step Azure guide. For the optional email-management skill, see the email rules interview.

  1. Register an Entra app (about ten minutes) — you need the client id, tenant id, and a secret. docs/entra.md
  2. Run the image with your filled-in relay.env.example, one replica, behind your HTTPS ingress on port 3000. For a work tenant, set MS365_MCP_ORG_MODE=true. Check it from outside with test/smoke.sh.
  3. Add the connector in Claude and upload the included skill. docs/claude.md
  4. Verify through Claude before anyone relies on it. docs/deploy-and-verify.md

Built for a public endpoint.

  • Each call is the user’s own. Every call is exchanged On-Behalf-Of the signed-in user, and Entra verifies the token at the exchange. Graph tokens live in memory.
  • Only your tenant. MS365_MCP_OBO_ALLOWED_TENANTS (and optionally named users) limits who may use it; anyone else gets 403 before any exchange.
  • Sign-in returns only to Claude. Redirect URIs are restricted to Claude’s callback, and dynamic client registration is off: Claude uses your client id.
  • Single-use file links. Attachment download and upload links are signed, single-use tickets held in memory, which is why the relay runs as one replica.
  • No mail content in the logs. Log files are bounded, and the audit trail is one JSON line per tool call — user, tool, status, sizes — with no mail content.
  • Pinned and checked. The image is pinned by digest and moved deliberately. CI runs the outside checks and the tool-surface test against the pinned image on every push and weekly.

What it isn’t.

M365 Claude Relay is not a hosted service — you run it, with your own Entra app registration. It holds no standing access to anyone’s mailbox, and it does not decide which tools a person may use: that is your scope list plus Claude’s tool permissions.
